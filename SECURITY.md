# Security Policy

## Scope

This repository contains intentionally vulnerable fixtures and local-only security experiments. They must never be deployed, exposed to the Internet, or connected to production credentials or data.

## Reporting a Vulnerability

Do not open a public issue for a suspected vulnerability that could expose a maintainer, a dependency, or a user. Use **Private Vulnerability Reporting**: open the repository's **Security** tab and select **"Report a vulnerability"**. Private advisories keep the report visible only to the maintainer until a fix is coordinated.

Include in the report:

- A concise description and impact.
- Reproduction steps using only synthetic data.
- The affected file and revision.
- Any mitigation or patch you can share safely.

Do not attach credentials, raw production data, exploit payloads for third-party systems, or private scanner output.

If the Security tab option is unavailable, temporarily open a minimal public issue that only asks for a private contact channel — without describing the finding.

## Response Expectations

This is a learning repository maintained on a best-effort basis. Reports are reviewed when time permits; no service-level agreement applies. If a report reveals a pattern that also affects third-party projects, coordinated disclosure with those projects takes precedence over an immediate public fix here.
